# DuckDB functionality

The Python code in this folder is intended to access DuckDB databases
that have been generated by annotating text or by converting from an
existing database of annotations. These databases are needed because
our process for annotating text (including CRFs) consist of the
following steps:
1. Text (including CRFs) to be annotated are collected.
   - Ideally, these will be stored as a DuckDB database so they can be
     annotated in parallel by a different or updated annotation engine.
   - Because we need to support CRFs, each Text will be identified with
     two identifiers: a document ID (required, may be a UUID or similar),
     section index (optional, integer) and a
     section title (optional, string). Texts should be grouped by document
     ID, then sorted by section index (ascending). Section text should be
     included in text to be annotated.
2. Annotations are generated for each text by a particular annotation
   engine or ingested along with the text. An AnnotatedBy LIST field
   is used to store the list of AnnotationEngineNames of every annotation
   engine that has been run on this Text -- this allows us to identify
   Text that still needs to be annotated with a particular annotation engine.
   Each annotation stores the document ID/section index/section title for the
   source text, the start and end index of the annotation (within the BodyText
   -- section headers will not be annotated unless they are included in the
   body text), the annotated text, and the ID, label and type of the
   annotation as per the annotation engine.

To meet these goals, every DuckDB database will have two tables:
- Texts
  - ID (primary key, autogenerated)
  - DocumentID (required) -- e.g. `PMID:24048470`, `PMC:PMC5479439`
  - Source (text)
  - SectionIndex (integer)
  - SectionTitle (text)
  - BodyText (text)
  - AnnotatedBy (list[text])
- Annotations
  - ID (primary key, autogenerated)
  - AnnotationEngine (text)
  - StartIndex (long, 0-based)
  - EndIndex (long, 0-based, inclusive)
  - Text (text)
  - ConceptID (text) -- must be whatever is specified by the annotation engine,
    not a normalized version
  - ConceptType (text) -- must be whatever type is specified by the annotation engine.

Normalization will add another table:
- Concepts
  - ID (primary key, autogenerated)
  - ConceptID (text) -- e.g. `MESH:C538271`
  - ConceptLabel (text) -- e.g. `Oculo-auriculo-vertebral spectrum`
  - ConceptType (text) -- MUST be a Biolink type
  - Identifiers (list[text]) -- list of CURIEs identifying secondary identifiers for this concept.
  - Synonyms (list[text])
- ConceptMappings
  - ID (primary key, autogenerated)
  - ConceptID (text)
  - MappedToID (text)
  - Source (text)
